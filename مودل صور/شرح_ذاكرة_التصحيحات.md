# 🧠 ذاكرة تصحيحات الروشتات — الشرح الكامل
### كيف تعلّم النظام من أخطائه؟ ماذا؟ لماذا؟ وبأي تقنيات؟

**النطاق**: ميزة HITL (Human-In-The-Loop Learning) — نظام يتعلم من تصحيحات الصيدلي بدون إعادة تدريب
**الحالة**: منفذة ومفعلة ومتحقق منها سلوكياً على القاعدة الحية — كوميت `662878b` + `a3267b3`

---

## 1️⃣ أنت بتقولله إنه غلط إزاي؟ (الاستخدام العملي — خطوة واحدة)

**أنت أصلاً بتقولله من غير ما تحس.** التدفق العملي بالضبط:

1. ترفع صورة الروشتة في المتجر (زي أي وقت)
2. تظهر النافذة بثلاث فئات:
   - 🟢 **مطابقة مؤكدة** → تدوس "اعتماد وإضافة للسلة" (وبتسجل موافقتك تلقائياً في حلقة قياس الدقة)
   - 🟡 **بحاجة لمراجعة** → النظام بيقترح 3 بدائل، **تختار الصح** وتدوس **"تأكيد وإضافة (يعلّم النظام)"**
   - 🔴 غير متوفر → لا بدائل (حماية)
3. **لحظة ما تدوس "تأكيد" على الأصفر، الدرس اتسجل للأبد** — ظهرت لك شارة "مصححة آلياً من ذاكرة التصحيحات" على البنود اللي النظام صححها بنفسه من دروسك

يعني **مفيش شاشة تعليم ولا خطوة إضافية**: نفس زر التأكيد اللي بتدوس عليه عشان تكمل شغلك — هو نفسه هو الدرّس.

---

## 2️⃣ بيتعلم منين؟ (مصدر الدروس)

| المصدر | مثال |
|---|---|
| **تجاوز الصيدلي** (الأهم) | OCR قرأ `protectoprilous 1 tab` والصيدلي اختار `Protectopril 20mg` → الزوج اتخزن |
| تكرار نفس الغلط | كل مرة نفس القراءة الغلط تتصحح، عداد الدرس (`hit_count`) يزيد — الأكثر تكراراً يظهر أولاً |
| ما زاد عنه | القراءات الصحيحة لا تُخزن كدروس — الذاكرة للأخطاء فقط |

المصدر الحقيقي الوحيد: **حقل `selected_drug_id` في مراجعة الصيدلي** (decision = overridden) — وده بيتسجل في جدول `ocr_corrections` بصيغة منقاة (`normalized`) فأي اختلاف حالة حروف أو مسافات بيضرب نفس الدرس.

---

## 3️⃣ بيتعلم إزاي تقنياً؟ (دورة الحياة)

```
┌─────────────────── دورة التعلم HITL ───────────────────┐
│                                                        │
│  1. رفع روشتة → OCR يقرأ → مطابقة كتالوج → عرض        │
│                                        ↓               │
│  2. صيدلي يصحح (تجاوز) ──────→ 📝 تسجيل الدرس         │
│     (قراءة غلط → اسم الدواء الصح)    normalize + upsert│
│                                        ↓               │
│  3. روشتة جديدة → OCR يقرأ نفس الغلط                  │
│                                        ↓               │
│  4. البحث في ذاكرة التصحيحات (normalized)              │
│     ✅ موجودة → استبدال فوري + شارة "مصححة آلياً"     │
│     ❌ مش موجودة → مسار المطابقة العادي + عرض للصيدلي │
│                                        ↓               │
│  5. القرار الجديد ممكن يصير درس جديد ←─ (الدورة تتكرر)│
└────────────────────────────────────────────────────────┘
```

**التقنيات المستخدمة**:

| التقنية | مكانها | الدور |
|---|---|---|
| **Text Normalization** (قبل التخزين والمطابقة) | `normalize_text` | تحويل الحالة والمسافات وفصل الأرقام — عشان `Protectoprilous 1 tab BID` و `protectoprilous 1 tab` يضربوا نفس الدرس |
| **Upsert + hit_count** | جدول `ocr_corrections` | فريد لكل (tenant, قراءة) — التكرار يزيد العداد بدل تكرار الصفوف |
| **Auto-Correction قبل المطابقة** | داخل endpoint التحليل | التصحيح يحدث **قبل** دخول محرك المطابقة — فالنتيجة النهائية تكون مطابقة تامة خضراء مش أصفر |
| **علم `auto_corrected`** | عمود على بنود التحليل | يوثق أي بند اتصلح آلياً — شفافية كاملة للصيدلي |
| **عزل المستأجر** | كل استعلام مقيّد بـ tenant_id | ذاكرة صيدلية لا تسرّب لصيدلية أخرى |

## 4️⃣ ما فايدته؟ (القيمة الحقيقية)

| القيمة | التفسير |
|---|---|
| **تحسن يومي بلا تكلفة** | كل يوم تشغيل = دروس جديدة = قراءات أقل أصفر — بدون ساعة GPU واحدة وبدون سحابة |
| **يهاجم الفجوة المقاسة** | فجوتنا الموثقة: ثقة 0.63 على الحقيقي مقابل 0.97 على الاصطناعي — الذاكرة تسد الفجوة **من واقع التشغيل** لا من بيانات وهمية |
| **يخفف عن الصيدلي تدريجياً** | أول أسبوع: كل الغلط المتكرر أصفر. بعد شهر: نفس الغلط أخضر تلقائياً — الصيدلي يراجع الجديد فقط |
| **شفافية كاملة** | شارة "مصححة آلياً" توضح لكل من يرى النظام أن القراءة دُرّست — لا وهم ذكاء |
| **أمان محفوظ** | التصحيح الآلي يمر بنفس صمامات CDSS (جرعات، LASA، عتبات) — الذاكرة تعلّم الاسم، والأمان باقٍ |

## 5️⃣ لماذا هذا التصميم بالذات؟ (القرارات الهندسية)

| القرار | السبب |
|---|---|
| **لماذا التعلم من التجاوز فقط وليس من كل إضافة سلة؟** | إضافة سلة على أخضر لا تعلم شيئاً (النظام صح أصلاً). التعلم يجب أن يأتي من **الخطأ المُصحح** — وإلا اتخزن ضجيج |
| **لماذا normalize قبل التخزين؟** | نفس الخطأ يُكتب بـ10 صور مختلفة (حالة/مسافة/وحدة) — التطبيع يجعلها درساً واحداً قوياً |
| **لماذا التصحيح قبل المطابقة وليس بعدها؟** | لو صححنا بعد المطابقة، القراءة الغلط ممكن تكون أخذت مسار LASA/OOD وحجبت النتيجة — التصحيح المبكر يجعل المسار كله نظيفاً |
| **لماذا جدول منفصل وليس إعادة تدريب؟** | إعادة التدريب = Colab + ساعات + مخاطرة انحدار. الجدول = تعلم **فوري، مراجع، قابل للحذف، وعزل لكل صيدلية** |
| **لماذا fire-and-forget في الواجهة؟** | فشل تسجيل الدرس **لا يجوز** أن يمنع صرف الدواء — التعلم ترف، والصرف وظيفة |
| **لماذا الشارة ظاهرة للصيدلي؟** | الثقة بالنظام تُبنى عندما يرى أن تصحيحه اتذكر واشتغل — شفافية HITL أساسية |

---

## 6️⃣ التقنيات المعمارية المستخدمة (المصطلحات الرسمية)

| المصطلح العالمي | تطبيقه هنا |
|---|---|
| **HITL (Human-In-The-Loop)** | الصيدلي في حلقة القرار — وتصحيحه يغذي النظام |
| **Experience Replay Table** | `ocr_corrections` = ذاكرة خبرة تشغيلية تُستعاد عند كل استدلال |
| **Online Learning (بدون أوزان)** | التعلم على مستوى **طبقة ما بعد المعالجة** — أسرع وأأمن من تعديل الأوزان |
| **Failure-Driven Learning** | نتعلم من الأخطاء المكتشفة فقط — الأعلى قيمة معلوماتية |
| **Graceful Degradation** | فشل التسجيل لا يعطل الصرف · فشل التطبيق لا يعطل التحليل |
| **Tenant Isolation** | كل صيدلية تتعلم دروسها — لا تلوث بين المستأجرين |

## 7️⃣ الحالة والتشغيل

| البند | القيمة |
|---|---|
| الجدول | `ocr_corrections` — مطبق حياً على القاعدة ✓ |
| عمود `auto_corrected` | مطبق على `prescription_items` ✓ |
| الواجهة | "تأكيد وإضافة (يعلّم النظام)" — تسجل المراجعة تلقائياً ✓ |
| endpoint القائمة | `GET /api/v1/prescriptions/corrections` (للطاقم) |
| الحلقة من الواجهة | **مقفولة بالكامل**: تأكيد الأصفر = درس، تأكيد الأخضر = نقطة قياس دقة |
| التحقق السلوكي | 5/5: إنشاء → تكرار → تطبيق → عدم المساس بالنظيف → تنظيف الاختبار |

> **الجملة للمناقشة**: *"نظامنا معمارياً مصمم يتعلم من تشغيله — كل تصحيح من الصيدلي يصبح درساً دائماً يُطبق آلياً على كل روشتة قادمة — محلياً، بلا سحابة، وبلا إعادة تدريب — وهذا هو جوهر أنظمة HITL في الصناعة."*
