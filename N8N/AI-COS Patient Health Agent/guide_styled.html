🏥 صيدلية AI-COS: وكيل التقييم الصحي الذكي

دليل المعمارية وسير العمل وتكامل الذكاء الاصطناعي (Patient Health AI Agent)

مشروع تخرج 2026 • AI-COS Pharmacy Architecture

1. نظرة عامة والهدف السريري والتجاري للمنظومة

يمثل وكيل التقييم الصحي الذكي (Patient Health AI Agent) الركيزة الأساسية للرعاية الصحية الذكية في منصة AI-COS. يقوم الوكيل بتحليل الحالة العلاجية للمريض فور دخوله إلى حسابه في صفحة البروفايل (/profile) لتقديم:

  • فحص التفاعلات الدوائية (Drug Interaction Safety): التأكد من عدم وجود تضارب بين الأدوية المزمنة الحالية والسابقة.
  • تنبيهات موعد إعادة الصرف (Smart Refill Alerts): حساب الأيام المتبقية في العبوة بدقة بناءً على تاريخ الاستهلاك.
  • استشارات سريرية مخصصة (Personalized Clinical Tips): صياغة نصائح طبية موجهة لحالته المزمنة (مثل مرضى الحساسية أو الضغط).
  • إشعار فوري لطاقم الصيدلية (Human-in-the-Loop Telegram Notification): إبلاغ الصيدلي بملخص الحالة ومعرف المريض.

2. معالجة وتجهيز البيانات قبل وصولها للسير (Pre-Processing Pipeline)

تتم معالجة البيانات وتنقيتها في واجهة المستخدم (Next.js) قبل إطلاق أي طلب نحو n8n عبر الخطوات التالية:

1
التحقق الأمني من الجلسة (Auth Session): يتم فحص وجود رمز دخول معتمد (Supabase JWT Token) لضمان خصوصية البيانات الطبية للمريض.
2
جلب بيانات البروفايل الرسمية (Profile Ingestion): يستدعي المتصفح نقطة الباك إند GET /api/v1/customers/me لجلب المعرف الفريد customer_id والاسم الحقيقي وتاريخ التسجيل.
3
الحساب الزمني لعضوية المريض (Tenure Calculation): يحسب كود المتصفح عدد الأيام المنقضية منذ تسجيل المريض بالمعادلة: 
days_since_join = Math.floor((Date.now() - new Date(created_at).getTime()) / (1000 * 60 * 60 * 24));
4
تغليف كائن الـ JSON (Payload Packaging): يتم تجهيز حزمة البيانات وإرسالها عبر مسار البروكسي الداخلي POST /n8n-webhook/aicos-patient-health.

3. التشريح الهندسي لسير عمل n8n عقدة بعقدة

[1. Webhook] ──▶ [2. Get Orders] ──▶ [3. Get Cycles] ──▶ [4. Build Prompt] │ [8. Respond] ◀── [7. Notify Admin] ◀── [6. Parse Response] ◀── [5. Ask Ollama]
اسم العقدة (Node) نوع العقدة (Type) الوظيفة والمسؤولية داخل المنظومة
1. Webhook Webhook Receiver استقبال حزمة البيانات المجمعة من المتصفح وحفظها في سياق التنفيذ.
2. Get Patient Orders PostgreSQL Query استعلام مباشر من Supabase لجلب آخر 5 طلبات حقيقية وأسماء الأدوية وإجمالي الفواتير.
3. Get Churn Data PostgreSQL Query استعلام من جدول دورات الاستهلاك (customer_cycles) لمعرفة متوسط أيام استهلاك العبوة وتاريخ آخر شراء.
4. Build Health Prompt Code Node (JS) حساب الأيام المتبقية في العبوة بدقة وصياغة البرومبت السريري المنظم لنموذج الذكاء الاصطناعي.
5. Ask Ollama HTTP Request استدعاء نموذج الذكاء الاصطناعي المحلي (AI-COS-LFM-Q4) عبر منفذ 11434 لتحليل الحالة بسرية تامة.
6. Parse Response Code Node (JS) تفكيك وتنظيم إجابة المودل إلى 3 أقسام سريرية واضحة (Interaction, Refill Alert, Recommendation).
7. Notify Admin Telegram Node إرسال إشعار فوري منسق بـ HTML إلى هاتف الصيدلي/الإدارة متضمناً معرّف المريض (Customer ID) وملخص حالته.
8. Respond Respond to Webhook إرجاع كائن الـ JSON النهائي للمتصفح ليظهر في البطاقة البنفسجية في صفحة البروفايل خلال جزء من الثانية.

6. أهم نقاط القوة لمناقشة مشروع التخرج (Graduation Defense)

★
معمارية الـ Agentic RAG الحقيقية: النظام لا يخمن الإجابات، بل يسترجع بيانات المريض التاريخية من SQL أولاً (Retrieval)، ثم يدمجها مع البرومبت (Augmentation)، ثم يولد التقييم (Generation).
★
الخصوصية والأمان الطبي (HIPAA / GDPR Compliance): استخدام نموذج محلي داخل Ollama يعني أن بيانات المرضى وأسماء أدويتهم الحساسة لا تغادر السيرفر الداخلي لأي طرف ثالث.
★
صمامات الأمان وعدم التعطل (Fault-Tolerant Design): تفعيل خواص alwaysOutputData يضمن استمرار السير حتى لو كان المريض مسجلاً لأول مرة بدون مشتريات سابقة.
