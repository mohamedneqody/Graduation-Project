## 1. نظرة عامة والهدف من النظام

في الصيدليات التقليدية، يعاني المرضى أصحاب الأمراض المزمنة (مثل الضغط والسكري والحساسية) من نسيان مواعيد تجديد الأدوية، مما يؤدي إلى:
1. تدهور الحالة الصحية للمريض (Medical Non-Adherence).
2. خسارة الصيدلية لمبيعات متكررة وتحول المريض لصيدلية منافسة (Customer Churn).

**نظام AI-COS Governance Reminders** يحل هذه المشكلة بالكامل ذاتياً (Autonomously) من خلال الربط بين:
* **قاعدة بيانات سحابية (PostgreSQL / Supabase)** لتخزين المعاملات.
* **محرك حسابي ونموذج تعلم آلة (XGBoost / Machine Learning)** للتنبؤ بموعد نفاد الدواء ونسبة خطر فقدان العميل.
* **محرك حوكمة سريرية (Human-in-the-Loop Governance)** لحماية المريض وفصل الحالات الآمنة عن الحالات الحرجة.
* **ذكاء اصطناعي توليدي (LLM / Ollama & Marketing Agent)** لصياغة عروض وخصومات تسويقية مخصصة.
* **منظومة أتمتة متعددة القنوات (n8n Multi-Channel Orchestrator)** لإرسال التنبيهات عبر Telegram و Email وتحديث قاعدة البيانات لحظياً.

## 2. المرحلة الأولى: كيف تتحول البيانات الأولية إلى معلومة ذكية؟

لا تبدأ العملية بمعلومات جاهزة، بل تمر البيانات بـ **4 مراحل تحويل داخل الباك إند (FastAPI)**:

```
[1. سجل مشتريات خام] ──▶ [2. حساب دورة الاستهلاك] ──▶ [3. نموذج Churn ML] ──▶ [4. محرك الحوكمة والقرار]
```

### 🔹 2.1 البيانات الأولية الخام (Raw Transactional Data):
عندما يشتري المريض دواءً، يُسجل في جداول `orders` و `order_items`:
* مُعرّف المريض: `customer_id`
* مُعرّف الدواء: `drug_id`
* تاريخ الشراء: `order_date`
* الكمية: `quantity` (مثلاً: 30 قرصاً).

### 🔹 2.2 الخوارزمية الرياضية لدورة الاستهلاك (Cycle Engine):
يقوم محرك الدورات (`customer_cycle/service.py`) بحساب معدل استهلاك المريض لكل دواء:
$$\text{avg\_cycle\_days} = \frac{\text{تاريخ آخر طلب} - \text{تاريخ أول طلب}}{\text{عدد مرات الشراء}}$$
* **توقع الموعد القادم:**
  $$\text{Next Refill Date} = \text{Last Purchase Date} + \text{avg\_cycle\_days}$$
* **مؤشر الثقة (`cycle_confidence`):**
  يقيس مدى ثبات المريض؛ إذا كان يشتري الدواء بانتظام شديد كل 30 يوماً، تكون نسبة الثقة قريبة من `1.0` (مثلاً `0.991`).

### 🔹 2.3 نموذج تعلّم الآلة للتنبؤ بخطر فقدان العميل (Churn Prediction Model):
يقوم نموذج التعلم الآلي (المُدرّب بـ **XGBoost**) بتحليل سلوك المريض ومقارنة الأيام المنقضية منذ آخر موعد متوقع:
* إذا حان موعد شراء الدواء وتأخر المريض لعدة أيام، ترتفع احتمالية الفقدان:
  $$\text{churn\_probability} = 0.9219 \quad (\text{أي 92.2\% خطر فقدان العميل})$$

### 🔹 2.4 محرك الحوكمة والقرار السريري (Governance Engine):
يقوم محرك الحوكمة (`governance/service.py`) بتطبيق مصفوفة القواعد الآمنة:
* **قاعدة التجاوز بسبب الخطر (Churn Override Rule):**
  إذا كان $\text{churn\_probability} > 0.70$ (أي أكبر من 70%)، يتم إلغاء الإرسال الآلي إجبارياً وتعيين القرار كـ:
  $$\text{decision} = \text{"human\_review"}$$
* **قاعدة الثقة العالية (Auto Send Rule):**
  إذا كان الخطر منخفضاً والثقة $\ge 0.80$، يُعين القرار كـ:
  $$\text{decision} = \text{"auto\_send"}$$

تُحفظ هذه النتيجة النهائية في جدول `pending_reminders` بانتظار معالجتها من سير عمل n8n.

## 3. المرحلة الثانية: كيف تنتقل المعلومة من السيرفر إلى سير عمل n8n؟

تنتقل البيانات من الباك إند إلى سير العمل عبر **نمط السحب الدوري المؤمّن (Scheduled Pull Pattern)**:

```
[n8n: Schedule Trigger (9 AM)]
       │
       ▼ (HTTP GET مع مفتاح X-Internal-Token)
[FastAPI Backend: /internal/governance/pending]
       │
       ▼ (SQL Query)
[Supabase PostgreSQL Database]
       │
       ▼ (JSON Array of 32 Items)
[n8n Workflow Engine]
```

### 🔒 الأمان والمصادقة المتبادلة (M2M Security):
لحماية مسارات السيرفر الداخلية، يُرسل n8n في الترويسة (Header):
```http
X-Internal-Token: dev-secret-key-12345-very-long-and-secure-32-chars
```
سيرفر FastAPI يتحقق من المفتاح عبر التابع `verify_internal_token` في ملف `dependencies/auth.py`.

### 📦 هيكل كائن البيانات (JSON Payload) الداخل إلى n8n:
لكل مريض، يستلم n8n كائناً بالشكل التالي:
```json
{
  "reminder_id": "6f98f3cd-db52-4676-a1fa-6d22939dcb35",
  "customer_id": "ddbf5eb0-6f6f-4bce-9880-96c8741544a5",
  "customer_name": "عمر عبد الله",
  "customer_phone": "+201162044293",
  "customer_email": "user_cbec5af9@example.com",
  "drug_name": "Amoclan 1g",
  "channel": "whatsapp",
  "decision": "human_review",
  "cycle_confidence": 0.991,
  "churn_probability": 0.9219,
  "predicted_days": 34.8,
  "status": "pending"
}
```

## 4. المرحلة الثالثة: التشريح التفصيلي لسير عمل n8n عقدة بعقدة

```
                ┌──────────────────────────────────────────────┐
                │        Schedule Trigger (Every 9 AM)         │
                └──────────────────────┬───────────────────────┘
                                       │
                                       ▼
                ┌──────────────────────────────────────────────┐
                │    0. Evaluate Due Reminders (Auto-Queue)    │
                └──────────────────────┬───────────────────────┘
                                       │
                                       ▼
                ┌──────────────────────────────────────────────┐
                │          1. Pull Pending Reminders           │
                └──────────────────────┬───────────────────────┘
                                       │
                                       ▼
                ┌──────────────────────────────────────────────┐
                │              2. Is Auto Send?                │
                └──────────────┬────────────────┬──────────────┘
                               │                │
                     [TRUE]    │                │    [FALSE]
             (قرار إرسال آلي) │                │ (مراجعة بشرية)
                               ▼                ▼
         ┌───────────────────────────┐    ┌───────────────────────────┐
         │    2.5 Marketing Agent    │    │ 3B. Alert Pharmacy Staff  │
         │ (توليد كود الخصم والرسالة)│    │ (تنبيه الصيدلي للمراجعة)  │
         └─────────────┬─────────────┘    └───────────────────────────┘
                       │
                       ▼
         ┌───────────────────────────┐
         │     3A. Send Telegram     │
         └─────────────┬─────────────┘
                       │
                       ▼
         ┌───────────────────────────┐
         │       3B. Send Email      │
         └─────────────┬─────────────┘
                       │
                       ▼
         ┌───────────────────────────┐
         │   4A. Mark as Sent in DB  │
         └───────────────────────────┘
```

---

### 🔹 العقدة 0: `Schedule Trigger (Every 9 AM)`
* **النوع:** `n8n-nodes-base.scheduleTrigger`
* **الوظيفة:** تبدأ دورة العمل أوتوماتيكياً كل يوم الساعة 9:00 صباحاً بدون تدخل بشري.

---

### 🔹 العقدة 1: `0. Evaluate Due Reminders (Auto-Queue)`
* **النوع:** `n8n-nodes-base.httpRequest`
* **الرابط المستهدف:** `POST http://host.docker.internal:8000/internal/cycles/recalculate`
* **الوظيفة:** يطلب من السيرفر تشغيل مهمة خلفية (Celery / Background Worker) لحساب كل المرضى الذين سينفد دواؤهم اليوم وإدراجهم في جدول `pending_reminders`.

---

### 🔹 العقدة 2: `1. Pull Pending Reminders`
* **النوع:** `n8n-nodes-base.httpRequest`
* **الرابط المستهدف:** `GET http://host.docker.internal:8000/internal/governance/pending`
* **الوظيفة:** يجلب جميع التذكيرات الجاهزة من قاعدة البيانات، ويحول كل مريض إلى عنصر منفصل (`Item`) يمر في المراحل التالية.

---

### 🔹 العقدة 3: `2. Is Auto Send?` (صمام الأمان والحوكمة)
* **النوع:** `n8n-nodes-base.if`
* **الشرط:** `{{ $json.decision }} Equal auto_send`
* **المسارات:**
  * **الفرع الأخضر (True Branch):** الحالات الآمنة والمستقرة ⬅️ تذهب للتنفيذ المباشر وتوليد الخصومات.
  * **الفرع البرتقالي (False Branch):** الحالات الحرجة (`churn > 70%`) ⬅️ تذهب لتنبيه الصيدلي لمراجعتها في لوحة التحكم (Human-in-the-Loop).

---

### 🔹 العقدة 4: `2.5 Marketing Agent` (وكيل التسويق بالذكاء الاصطناعي)
* **النوع:** `n8n-nodes-base.httpRequest`
* **الرابط المستهدف:** `POST http://host.docker.internal:8000/api/v1/agents/marketing/generate-campaign`
* **جسم الطلب (Payload):**
  ```json
  {
    "customer_name": "{{ $('1. Pull Pending Reminders').item.json.customer_name }}",
    "drug_name": "{{ $('1. Pull Pending Reminders').item.json.drug_name }}",
    "discount_percentage": {{ $('1. Pull Pending Reminders').item.json.churn_probability > 0.4 ? 15 : 0 }}
  }
  ```
* **الوظيفة:** يستدعي نموذج اللغة التوليدي (LLM) ليقوم بـ:
  1. فحص نسبة الخطر: إذا كانت $> 40\%$ يمنح المريض خصم **15%** مع توليد كود كوبون فريد.
  2. صياغة نص تسويقي طبي دافئ ومخصص باسم المريض واسم دوائه.

---

### 🔹 العقدة 5: `3A. Send Telegram` (التنبيه الفوري عبر تليجرام)
* **النوع:** `n8n-nodes-base.telegram`
* **الوظيفة:** يرسل رسالة فورية ومنسقة بـ HTML للمريض على حسابه في Telegram تحتوي على:
  * اسم الصيدلية والترحيب.
  * اسم الدواء المجدول.
  * كود الخصم (إذا تم منحه).
  * زر مباشر لإعادة الطلب.

---

### 🔹 العقدة 6: `3B. Send Email` (البريد الإلكتروني الاحترافي)
* **النوع:** `n8n-nodes-base.emailSend`
* **الوظيفة:** يرسل بريداً إلكترونياً مصمماً بتنسيق Responsive HTML احترافي يتضمن:
  * بطاقة الدواء وصورته.
  * شارة الخصم والكوبون بتصميم جذاب.
  * زر استكمال إعادة الطلب بنقرة واحدة (One-Click Reorder).

---

### 🔹 العقدة 7: `4A. Mark as Sent in DB` (تحديث قاعدة البيانات)
* **النوع:** `n8n-nodes-base.httpRequest`
* **الرابط:** `PATCH http://host.docker.internal:8000/internal/governance/{reminder_id}/status?status=sent`
* **الوظيفة:** يخبر السيرفر بتحديث حالة التذكير في جدول `pending_reminders` إلى `sent`، لمنع تكرار إرسال التنبيه لنفس المريض في نفس اليوم.

---

### 🔹 العقدة 8: `3B. Alert Pharmacy Staff` (تنبيه الحالات الحرجة)
* **النوع:** `n8n-nodes-base.httpRequest / Telegram`
* **الوظيفة:** إذا خرج التذكير بمسار `human_review`، ترسل هذه العقدة إشعاراً فورياً على تليجرام إدارة الصيدلية لتنبيه الصيدلاني بضرورة مراجعة حالة المريض واعتمادها من شاشة `AI Review Queue` في لوحة التحكم.

## 6. دليل المناقشة لمشروع التخرج (Graduation Defense Highlights)

عندما يسألك الدكتور أو لجنة المناقشة: **"ما الجديد الذي يقدمه هذا السير عن مجرد بوت تليجرام أو رسائل عادية؟"**

إليك الإجابة الاحترافية:
1. **أولاً: التكامل المعماري (Full End-to-End Orchestration):**
   * النظام لا يعمل بمعزل، بل هو حلقة وصل متكاملة بين **قاعدة بيانات Supabase**، **سيرفر FastAPI**، **محرك n8n**، و**نماذج الذكاء الاصطناعي**.
2. **ثانياً: الحوكمة السريرية ورقابة الإنسان (Human-in-the-Loop Governance):**
   * لا نترك الذكاء الاصطناعي يتخذ قرارات طبية بمفرده بدون صمامات أمان؛ الحالات ذات الخطر المرتفع تخضع لمراجعة الصيدلاني البشري أولاً.
3. **ثالثاً: التسويق الذكي الموجه (Dynamic AI Incentive):**
   * الخصومات لا تُمنح للجميع عشوائياً، بل تُمنح فقط للعميل المعرض لمغادرة الصيدلية لتعظيم أرباح الصيدلية (Maximize ROI) والحفاظ على ولاء المرضى.
