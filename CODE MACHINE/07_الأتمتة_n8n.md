## نمط التشغيل: Pull لا Push — وسبب الاختيار

```
كل صباح (Schedule Trigger)
   ▼
HTTP Request → GET /api/v1/internal/governance/pending     (n8n يسحب بنفسه)
   ▼
فلترة + صياغة رسالة (بلا PII — [[الاسم]] فقط)
   ▼
إرسال WhatsApp/SMS/Telegram
   ▼
POST /api/v1/agents/automation/callback                    (يكتب النتيجة والمقاييس)
        → جدول automation_runs = حلقة قياس مغلقة
```

**ليه Pull مش Push؟** لو النظام دفع (push) وn8n واقف = التذكير ضاع بصمت. بالسحب، التذكيرات تبقى في `pending_reminders` حتى يرجع n8n — **فشل مؤقت لا يفقد بيانات**. + worker إعادة محاولة (60 ثانية، backoff 5 دقائق، حد 3).

## الأمان في الاتصال

- كل نداء n8n → الباك-إند يحمل `X-Internal-Token` (مقارنة timing-safe)
- المتصفح لا يعرف هذا التوكن — فصل تام بين مسار الإنسان ومسار الخدمات
- كل callback يُوثق في `audit_logs` (بعد إصلاح `log_id` أصبح التسجيل يعمل فعليًا في كل المواضع)
