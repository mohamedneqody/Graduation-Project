# 08 — الأمان والحوكمة (Security & Governance)

## 1. المصادقة والصلاحيات

- **Supabase GoTrue** للهوية (JWT) — الباك-إند يتحقق ويجلب الدور من `customers.role`
- ثلاث طبقات: عام / أدمن (`require_role`) / خدمة داخلية (`X-Internal-Token` timing-safe)
- **مثبت حيًا:** حساب بدور customer حاول فتح لوحة الأدمن → رفض فوري (20-09-2026)
- جلسات مُدارة (`models/session.py`) + إلغاء جلسة عند الخروج

## 2. WORM Ledger — سجل لا يُتلاعب به

```
سجل 1: SHA256(محتوى)  →  سجل 2: SHA256(محتوى + توقيع السابق)  →  ...
```
- دفتر **خارج** قاعدة البيانات (`core/worm_ledger.py` + worker)
- أي حذف/تعديل بأثر رجعي يكسر السلسلة بأكملها ويكشف نفسه
- حتى مدير قاعدة البيانات (DBA) لا يستطيع "تنظيف" تاريخ فعل
- `WormHeartbeatBadge` في اللوحة يعرض نبضته حية

## 3. البوابات القسرية (Hard Gates) — الأمان بالكود

| البوابة | أين | القاعدة |
|---|---|---|
| بوابة نشر الخصم | What-If Lab | loss/danger/خصم صفر → زر مقفول + رفض 422 من السيرفر |
| بوابة التداخلات CDSS | الروشتات/البيع | تداخل خطير → فوق رأي أي نموذج → تصعيد |
| 22 كلمة خطر | المحادثة الطبية | تصعيد بشري إجباري |
| بوابة مطابقة OCR | الروشتات | ثقة < 0.40 رفض، < 0.60 مراجعة بشرية |
| بوابة الاستبقاء | وكيل التسعير | تكلفة الاستبقاء ≥ صافي ربح العميل → هجر الاستبقاء |

## 4. الخصوصية (PII)

- أسماء المرضى **لا تغادر الجهاز**: علامة `[[الاسم]]` في كل برومبت، استبدال محلي بعد الرد
- إخفاء هوية كامل بمطابقة قانوني: `privacy_account_anonymized_law_151` (القانون 151) مع سجل تدقيق
- البيانات الحساسة للروشتات معزولة وثقة الاستخراج ظاهرة في كل موضع

## 5. عزل المستأجرين (RLS)

كل جدول أعمال: `USING (tenant_id = current_setting('app.current_tenant_id'))` — العزل على **مستوى قاعدة البيانات**، لا يعتمد على سلامة كود التطبيق وحده.

## 6. حماية الطبقة الخدمية

- **Rate limit 30 طلب/دقيقة** على كل نقاط الوكلاء (كل نداء مكلف توكنز)
- **X-Internal-Token** بمقارنة `secrets.compare_digest` (مقاومة توقيت)
- نمط Outbox للرسائل — لا فقدان تحت الضغط أو الانقطاع
- خطأ الإدخال محصور بـ Pydantic (أنواع وحدود صارمة على كل نقطة)

## 7. حوكمة القرار الآلي (أهم فصل للجنة BIS)

كل قرار آلي في المشروع يمشي بدورة **وحدة واحدة**:

```
بيانات مصدر معلن → محرك حسابي/ML → قرار → تفسير (SHAP/صيغة) → سجل تدقيق → مراجعة بشرية عند الحاجة
```

- فاحص الامتثال **يستطيع أن يرفض** (NEEDS_ATTENTION) — مثبت تحت تلاعب مقصود
- كل إخفاء هوية، كل كوبون، كل تشغيل n8n، كل نشر محاكاة → سجل تدقيق (بعد إصلاح `log_id` في 20-09)
- صفحة `risk-register` توثق المخاطر ومصفوفة الفصل بين المهام (SoD) — حوكمة كنظام مكتوب لا كشعار
