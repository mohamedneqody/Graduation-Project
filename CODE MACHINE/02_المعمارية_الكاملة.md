# 02 — المعمارية الكاملة (Architecture)

## 1. النمط العام: Monorepo بطبقات واضحة

```
AI-COS-Pharmacy\
├── backend\                     ← FastAPI (Python 3.14, async)
│   ├── app\main.py              ← نقطة التجميع (350 سطر): 27 راوتر + 4 عمال خلفيين
│   ├── app\domains\             ← 27 دومين (كل وظيفة في مجلد: router/service/schemas)
│   ├── app\core\                ← البنية المشتركة: WORM، rate limits، verticals، n8n client
│   ├── app\dependencies\        ← الصلاحيات والجلسات
│   ├── app\models\              ← 15 ملف ORM (SQLAlchemy 2.0 Mapped)
│   ├── app\domains\prediction\  ← نماذج ML + ملفات .joblib في backend\models\
│   ├── scripts\                 ← خطوط التدريب (build_features.py, train_churn_v2.py)
│   ├── migrations\              ← 7 سكربتات SQL + مشغّل idempotent
│   └── tests\                   ← 26 ملف اختبار (158 اختبارًا)
├── frontend\                    ← Next.js 15 (App Router, TypeScript)
│   └── src\app\                 ← (storefront) العميل + (admin) اللوحة + (auth)
├── docs\                        ← 15+ مستند هندسي + قوالب n8n
└── scripts\start-aicos.ps1      ← مشغل المنظومة (باك :8000 + فرونت :3000)
```

**لماذا Domains؟** كل وظيفة عمل (طلبات، مشتريات، محاسبة، حوكمة...) معزولة بمجلدها — إضافة ميزة لا تلمس غير مجلدها (Additive-Only بالتصميم).

## 2. تدفق الطلب الكامل (مثال: عميل يشتري)

```
موقع العميل (Next.js)
   │ fetchApi (JWT من Supabase + إعادة محاولة تلقائية)
   ▼
FastAPI :8000
   │ ① المصادقة: JWT من Supabase GoTrue → الدور من جدول customers
   │ ② Rate limit: 30 طلب/دقيقة على الوكلاء (n8n الداخلي يعبر بـ X-Internal-Token)
   │ ③ الـ Router يستدعي الـ Service المناسب
   │ ④ الكود يحسب (معادلات/SQL) ← الـ LLM يصيغ إن لزم (بـ [[الاسم]] بلا PII)
   │ ⑤ كتابة البيانات + سجل audit_logs
   ▼
PostgreSQL (Supabase) — RLS لكل tenant
   │
   ├── n8n يسحب (poll) التذكيرات المعلقة → يرسل WhatsApp/SMS → callback يكتب النتيجة
   └── WORM worker يدفع بصمة التدقيق لدفتر خارجي متسلسل SHA-256
```

## 3. طبقة الصلاحيات (3 مستويات)

| المستوى | الدالة | من يدخل؟ |
|---|---|---|
| عام | بدون حماية | الصفحات العامة للعملاء |
| أدمن فقط | `require_role("admin","super_admin")` | كل لوحة التحكم + نماذج ML |
| أدمن أو خدمة داخلية | `require_admin_or_internal` | المتصفح (أدمن) أو n8n (توكن خدمة) |

**مثبت حيًا:** حساب بدور `customer` حاول فتح `/admin/what-if` → رفض وتحويل تلقائي (20 سبتمبر 2026).

## 4. المعمارية متعددة المستأجرين (Multi-tenant)

- كل جدول أعمال فيه `tenant_id` مفهرس
- **RLS** (Row Level Security) في Postgres: سياسة `tenant_id = current_setting('app.current_tenant_id')`
- الجلسة تضبط سياق المستأجر لكل اتصال — صيدلية لا ترى بيانات صيدلية أخرى **حتى لو كتبت SQL يدويًا**

## 5. طبقة الحزم العمودية (Vertical Packs)

```
app/core/verticals/loader.py  ← يقرأ YAML الحزمة عند الإقلاع (fail-safe → pharmacy)
packs/pharmacy.yaml           ← الوحدات والقواعد والغطاء 18%
packs/coffee.yaml             ← 12%
packs/apparel.yaml            ← 50%
```
النواة محايدة للأعمال — الصيدلية مجرد "حزمة". التبديل بمتغير بيئة واحد. نفس الكود يخدم 3 تجارات = **إثبات قالب Business OS**.

## 6. طبقة الذكاء: تقسيم صارم للمسؤولية

| المكون | يقرر؟ | التفصيل |
|---|---|---|
| نماذج ML (churn/دورة) | **يقدّر احتمالات وأرقامًا** | XGBoost + SHAP — لا يلمس المال مباشرة |
| المحركات القطعية | **يحسب القرار المالي والسريري** | simulator / pricing / math_engine / interaction_guard |
| الوكلاء التسعة | **ينفذون سير عمل** | كل وكيل = ملف بايثون + حدود صلاحية |
| الـ LLM | **يصيغ لغة فقط** | داخل حدود نصية مفروضة، بلا أرقام حرة |

**سير قرار كامل (الاستبقاء):** نماذج ML تتنبأ بالانقطاع → محرك التسعير القطعي يحول الاحتمال لأرقام مالية (تكلفة استبقاء/خسارة متوقعة/ROI) ويرفض أي خصم يكلّف أكثر من ربح العميل → الـ LLM يكتب المبرر بالعربية.

## 7. العمال الخلفية (Background Workers في lifespan)

1. **WORM worker** — دفع سجلات التدقيق للدفتر الخارجي المتسلسل
2. **automation_retry_worker** — إعادة محاولة الأتمتة الفاشلة (60 ثانية، backoff 5 دقائق، حد 3)
3. **Webhooks processor** — نمط Outbox للرسائل المضمونة
4. **Backup service** — نسخ احتياطي

## 9. مبادئ هندسية مقررة ومكتوبة (أسلوب العمل)

1. **Additive-Only**: الميزات الجديدة ملفات/جداول/نقاط جديدة — لا كسر للقديم
2. **Fail-safe**: أي فشل LLM/SHAP/cache = سلوك بديل محدد مسبقًا، لا انهيار
3. **Provenance داخل المنتج**: ملفات النماذج تحمل بروفة نسختها (تاريخ/معاملات/مقاييس)
4. **الصدق فوق الشكل**: أصفار صادقة أفضل من أرقام مزيفة
5. **كل إصلاح له migration موثق** بسكربت idempotent قابل لإعادة التشغيل
